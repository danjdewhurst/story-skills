# Changelog

All notable changes to Story Skills are recorded here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project uses [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

Add an entry under `## [Unreleased]` in the same pull request as any change a user would notice, especially changes to the project format (schema), CLI behaviour, and skill instructions. Users of copied skill installs run the bundled fallback CLI, so they need to know when its behaviour changes. `bun run release` refuses to release while `Unreleased` is empty, and moves its entries under the new version. See [CONTRIBUTING.md](CONTRIBUTING.md#changelog).

This file was started after 0.15.0. Entries for 0.15.0 back to 0.12.0 come from the commit history; older releases are summarised more briefly from their [GitHub release notes](https://github.com/danjdewhurst/story-skills/releases), which list every pull request.

## [Unreleased]

### Changed

- A boolean flag now takes a value only as `--flag=value` (`--heading=false`, `--baseline=false`, `--json=false`), and a boolean word right after a bare flag (`true`, `no`, `0`, and the rest, in any case) is refused with exit 2. So `story add chapter --dry-run No Way Back`, which used to write a chapter titled "Way Back", now writes nothing; put the flag after the title, or the title after `--`. ([#549](https://github.com/danjdewhurst/story-skills/issues/549))
- `story add` refuses an option the kind does not read, with exit code 2 (`--number does not apply to story add scene`), where it used to ignore it, and `story help add` lists each kind's options. Only the plural list flags (`--characters`, `--aliases`, `--themes`, and the like) split on commas, so `--alias "Rite of Ash, the"` is one alias; a comma in a singular id flag such as `--character` or `--used-in` is now an error. ([#576](https://github.com/danjdewhurst/story-skills/issues/576))

### Fixed

- `cli-defaults` in `story.md` can no longer name `split` or `merge`, so a default `at` cannot make `story split chapter-01` split without `--at`. `story validate` reports such an entry, and other commands refuse to run until it is gone, as for `add`, `rename`, `move`, `remove`, and `knowledge`. ([#566](https://github.com/danjdewhurst/story-skills/issues/566))
- `story check` refuses to run with exit code 3 while `cli-defaults` or `severity` in `story.md` is invalid, as `links` and `continuity` do. Before, it ran without the project's severity overrides and exited 1. ([#566](https://github.com/danjdewhurst/story-skills/issues/566))
- An error ends with `(story.md cli-defaults set ...)` only when it is about a flag a default filled in, such as an `--out` file it cannot write. Before, any error that held a default's value blamed it, so `story progress --date 2024-13-02` blamed a default `weeks: 2`. ([#566](https://github.com/danjdewhurst/story-skills/issues/566))
- Every `cli-defaults` flag of a linked group now applies: `build` defaults of `format: html` and `stamp: draft-2` give a stamped review copy, where only the first was used. A flag of the group on the command line still drops them all. ([#566](https://github.com/danjdewhurst/story-skills/issues/566))
- `schemas/story.schema.json` now refuses a date that is not a real day, such as `2024-13-45` or `2023-02-29`, as `story validate` does. This covers `deadline`, `publication-date`, `release-start`, chapter `release-date`, progress sessions, and a chapter or scene `date` shaped `YYYY-MM-DD` in a book without a story `calendar`; the leap-year-aware pattern is generated from validate's own date check. ([#530](https://github.com/danjdewhurst/story-skills/issues/530))
- The schema now refuses `writing-mode: vertical` with a language set horizontally, such as `language: en`, and `chapter-numerals: native` with a language that prints 0-9, as `story validate` does. The language tags it allows for each are generated from the language, script, and numeral tables validate reads. ([#529](https://github.com/danjdewhurst/story-skills/issues/529))
- The schema and the CLI now agree on `continuity/state.md` entries, research `used-in`, and route `mode`. The schema requires the `character`, `artifact`, and `knows` that `story continuity` already required, and takes any non-empty text in `used-in`, which `story links` still checks. `story validate` now asks for quotes around a route `mode` written as a number or `true`, which the codex dropped, and reports a progress session whose `date` is blank or a list, which `story progress` left out or read wrongly. ([#565](https://github.com/danjdewhurst/story-skills/issues/565))
- An empty `--path`, positional project path, `--dir`, `--follows`, `--precedes`, or `--against` is a usage error instead of the current directory, so `story reindex --path "$UNSET"` or `story import ms.md --dir "$UNSET" --force` changes nothing, as `--out ""` already did. ([#576](https://github.com/danjdewhurst/story-skills/issues/576))
- `story prose` now counts each style-sheet sample file once in its baseline, however often `samples` names it. Before, `chapters/chapter-01.md` and `./chapters/chapter-01.md`, or a file listed both on its own and inside a listed folder, were added to the profile twice. `validate` and `prose` warn `style-sample-duplicate` for an entry that names the same file or folder as an earlier one. ([#523](https://github.com/danjdewhurst/story-skills/issues/523))
- A right-to-left book's print contents now show their page numbers when rendered with WeasyPrint. The numbers still sit at the left margin, but are now placed there without the float that WeasyPrint dropped; left-to-right and vertical books are unchanged. The publishing skill and the docs now also say that Chrome's print to PDF leaves the contents page without page numbers in every book. ([#591](https://github.com/danjdewhurst/story-skills/issues/591))
- EPUB and DOCX builds are now byte-identical whether `story` runs under Bun, Node, or the bundled fallback. Before, the HTML builds matched but the ZIP entries were compressed by each runtime's own zlib, which gave different bytes. The CLI now compresses them with its own deflate encoder, and the files stay about the same size. ([#589](https://github.com/danjdewhurst/story-skills/issues/589))
- The CLI no longer writes frontmatter it cannot read back, and a rewrite keeps inline comments and flow lists. Values holding U+2028, U+2029, DEL, or a C1 control are written as `\u` escapes and numbers in plain decimal rather than `1e+21`, and `init`, `add`, and `rename` refuse a title or name with a line break, U+2028, or U+2029. `True`, `TRUE`, `False`, and `FALSE` now read as booleans, as in YAML 1.2, so quote a text field written that way (`title: "True"`); a carriage return with no line feed after it is reported as `Unsupported line break`. ([#550](https://github.com/danjdewhurst/story-skills/issues/550))
- The repository's check scripts now reject inputs they used to pass. `check:metadata` checks every Bun pin in every workflow, not only the first `bun-version` in `ci.yml`, and `check:links` fails a link that leaves the repository and now also covers `CHANGELOG.md`, `AGENTS.md`, `SECURITY.md`, every `.md` file under `.github/`, and `evals/README.md`. `test:coverage` drops its branch gate, which never ran because Bun's lcov report has no branch records. ([#570](https://github.com/danjdewhurst/story-skills/issues/570))
- `story rename` no longer claims to finish an interrupted rename for an id that never existed. `story rename character no-such-person "Sera Voss"` now fails with `character no-such-person does not exist`, as does a rerun of a rename that already finished. A rename now writes a marker (`.story-rename.tmp`) before its first change and deletes it after its reindex, and a rerun resumes only when that marker names the same rename. ([#579](https://github.com/danjdewhurst/story-skills/issues/579))
- `story validate` now warns when a hand-made character shares its id with a faction or an artifact (`shared-id`). `rename` and `remove` now list the `mentions`, `owner`, and `controlled-by` references they leave alone because those could mean either entity (`ambiguous-references`); before, those references silently came to name the other entity. ([#579](https://github.com/danjdewhurst/story-skills/issues/579))
- A write that finds something already at its temporary file's name now says so in plain words (`Cannot write to chapters/chapter-01.md: something is already at the name of its temporary file (.chapter-01.md.story-<random>.tmp, in the same folder), so it was left as it is. Run the command again`) instead of ending in `EEXIST`. `story validate` now also reports a symlink, folder, or other entry that is not a regular file at a temporary file's name (`interrupted-write`), without following a symlink, and says to delete a symlink itself rather than what it points to; before, it reported only regular files there. ([#602](https://github.com/danjdewhurst/story-skills/issues/602))
- `scripts/issue-worktree.sh`, the contributor helper that gives each automated agent run its own worktree, no longer hands back a worktree on a different branch from the one asked for, or puts worktrees inside the shared checkout. A rerun that asks for another branch now fails. Worktrees go beside the checkout's `projects` folder in any letter case, or under `ISSUE_WORKTREE_ROOT`, which a checkout under no `projects` folder must set. ([#572](https://github.com/danjdewhurst/story-skills/issues/572))
- A cloned project or a pull request can no longer hang `story` in CI with a file linked to `/dev/zero` or made a FIFO. `story.md` (read for `cli-defaults`), `.story.lock`, the workflows `story doctor` checks, and a codex folder's `index.html` are now read like every other project file, and every read also checks the opened file, so a file swapped in while a command runs is refused. A write checks its folder again just before it lands, so a folder swapped for a symlink mid-write cannot carry the file outside the project. ([#548](https://github.com/danjdewhurst/story-skills/issues/548))
- revision-continuity's draft snapshot and editorial-review's editor round now commit only the book's folder (`git add -A -- .`, `git commit -m "…" -- .`), as feedback-triage does. Before, their `git add -A` also staged files from elsewhere in a larger repository. All three skills now show `git status` for the folder first and ask before a private file it lists, such as a `.env`, goes into the commit. ([#598](https://github.com/danjdewhurst/story-skills/issues/598))
- `--out`, `init`, and `import` now refuse every name a disk reads as `.git`, and `--out` every name a disk reads as project source, on every system. That is a name with an NTFS stream after a colon (`.git::$INDEX_ALLOCATION`, `story.md::$DATA`), trailing dots or spaces (`GIT~1.`, `story.md.`), an NTFS short name (`CHAPTE~1`, `STYLE-~1.MD`), or zero-width and other characters HFS+ ignores; Linux reaches these disks too, through WSL's `/mnt/c` or a USB stick. The path as typed is checked before anything resolves it. ([#603](https://github.com/danjdewhurst/story-skills/issues/603))
- A serial's release schedule now ends at the last chapter once `story.md` has `status: complete`, so `story progress` and `story next` no longer project episodes past it or warn `release-undrafted` that they have no chapter. Chapters still to come keep their dates. When every chapter has a release date, the line marks the final one `(…, the last episode)` and, after it, reads `Next release: none, the story is complete; episode <n> (<chapter>) on <date> was the last`; `--json` adds `data.release.complete` and `data.release.last`. ([#583](https://github.com/danjdewhurst/story-skills/issues/583))
- A book that dates only some chapters now reads in one story order everywhere, the same in Bun and Node. Where date and chapter-number comparisons went in a circle, `story continuity`, `story knowledge --at`, `story move chapter`, `story series`, and `story diagram` could disagree with each other or differ by runtime; now an undated chapter takes the latest date among the chapters read before it, so a flashback also comes before the undated chapters read since then. Books whose dates never went in a circle read as before. ([#545](https://github.com/danjdewhurst/story-skills/issues/545))
- `story snapshot --restore` no longer deletes a file whose name differs from the snapshot's only in letter case on a file system that ignores case, such as macOS and Windows by default. Before, `notes.md` (for the snapshot's `Notes.md`) and every file in a `Chapters/` folder were deleted, even right after the restore wrote them; now they get the snapshot's text under the project's spelling, found by asking each folder whether a name reaches the same file. ([#581](https://github.com/danjdewhurst/story-skills/issues/581))
- `story snapshot --restore` now removes the folders its deletes leave empty, and lists each as `rmdir` in its output, `--dry-run`, and `--json` (`data.removedFolders`). A folder that was already empty, one that still holds anything, and the folders `init` makes are kept, and one that cannot be removed is a `folder-not-removed` warning rather than a failed restore. ([#524](https://github.com/danjdewhurst/story-skills/issues/524))
- A second death after a revival, recorded as a status progression to `deceased` after `revived-in`, now counts without a progression back to `alive` and gets the right advice. `story validate` no longer asks to set `died-in` to it (`deceased-without-died-in`), which would erase the first death, and `story continuity` accepts `status: deceased` (`revival-status-mismatch`) once that chapter is drafted. In a branching book these checks and the `story series` and `story diagram` lifelines read the choices' reading order instead of chapter numbers. ([#584](https://github.com/danjdewhurst/story-skills/issues/584))
- `story rename --prose` no longer rewrites link targets, HTML tags, URLs, or initials, and lists the matches it cannot safely rewrite for you to check. Link and image destinations, reference definitions, autolinks, HTML tags, and bare URLs and email addresses keep the old name, and an initial such as the `J` of `J. R. Dunn` is no longer looked for, here or in `story mentions` and `story continuity`. Possible ordinary words (`May` of May Dunn, or `Rose` opening a sentence in a chapter that says "a rose") and the text of a reference link whose label is defined (`[Ines]`) are left as written and listed after the summary, with `--dry-run` too, and in `data.prose.review` with `--json`. ([#546](https://github.com/danjdewhurst/story-skills/issues/546))
- `story mentions` and `rename --prose` print a control character in an excerpt as U+FFFD, so an escape sequence in a chapter no longer reaches the terminal. ([#546](https://github.com/danjdewhurst/story-skills/issues/546))
- `story mentions` and `rename --prose` find a name at the right place in text where a CJK compatibility ideograph changes length when composed to NFC. Before, such a name could get the wrong column and excerpt, and `rename --prose` skipped it as an alias. ([#588](https://github.com/danjdewhurst/story-skills/issues/588))
- `story prose` analyses a line of prose that opens with `#`, such as `#1 on the list was Mara`; only a heading (one to six `#` and a space) is dropped. ([#588](https://github.com/danjdewhurst/story-skills/issues/588))
- `story links` and `story check` accept an abandoned promise or clue whose `planted` or `payoff` chapter, or an abandoned question whose `introduced` chapter, was never written, as `story continuity` already did; a question's `resolved` chapter must still exist. `story add` follows the same rules, and now also refuses a dropped thread's unwritten `--planted` chapter and a chapter id that is neither written nor `chapter-NN`, which `story links` rejects. `story add chapter` and `story split` warn (`adopted-references`) when an abandoned thread already names the new chapter. ([#582](https://github.com/danjdewhurst/story-skills/issues/582))
- The story id is never empty. When neither the `story.md` title nor the project folder name has ASCII letters or digits, it is `story-` and a hash of the title (or of the folder name), and `validate` and `build` warn with `substitute-story-id`; before, builds wrote `dist/.epub` with an empty EPUB identifier, and every such book shared one Twine IFID. ([#577](https://github.com/danjdewhurst/story-skills/issues/577))
- `--out` no longer replaces the `cover` or `build-style` `css` file that `story.md` names, and a cover whose first bytes are not the image its extension names fails `validate` and the EPUB build. A `cover` or `css` path with a NUL, another control character, or a bidirectional control is now an error that names the field, with exit code 3, and so is an unreadable cover. ([#577](https://github.com/danjdewhurst/story-skills/issues/577))
- Export and builds refuse a matter page with text and a blank `title`, which gave an invalid EPUB. ([#577](https://github.com/danjdewhurst/story-skills/issues/577))
- A markdown build of a book whose story id is `manuscript` now writes `dist/manuscript.book.md`, so it no longer replaces the `dist/manuscript.md` that `story export` writes. ([#526](https://github.com/danjdewhurst/story-skills/issues/526))
- Write commands no longer lose a file saved while they run: `move`, `rename`, `merge`, `remove`, and `snapshot --restore` keep a file changed after they read it instead of deleting or replacing it, and every rewrite, the registries and `story.md` included, checks for changes on disk. `progress --log`, `passes --init`, `--start`, and `--done`, and `init --force` now hold the project lock, and on Linux a lock records its process's boot, pid namespace, and start time, so a lock an earlier run left with the same process number (as in a container) is taken over rather than waited on, while one from another container sharing the host name goes by age. ([#547](https://github.com/danjdewhurst/story-skills/issues/547))
- When the project lock cannot be created, such as in a project folder you cannot write to, a command that needs to write now refuses with exit code 4 before changing anything instead of running unlocked; one with nothing to change still succeeds. `init --force` and `import --force` into an existing folder without `story.md` take the lock too. ([#601](https://github.com/danjdewhurst/story-skills/issues/601))
- `bun run release` no longer leaves a half-made release behind when a step fails. A failure before anything reaches origin, a refused push included, undoes only the release's own commit, tag, and file changes; a failed `gh release create` after the tag push prints how to finish the release. `--dry-run` now also refuses a changelog that already has a section for the new version. ([#571](https://github.com/danjdewhurst/story-skills/issues/571))
- When `story` is not installed, skills now run the bundled `story-maintenance/scripts/story.js` with Node, by absolute path from the story project folder, instead of `bun run story --`. Bun runs a package script from the checkout's root, so `.` named the Story Skills checkout: `validate` failed with `is not a story project`, and `init` would have created the book inside the checkout. A checkout's `bin/story.js` is used only when the user names it or the agent is working in it, and never with Bun, which would load the story folder's `bunfig.toml` and `.env`. ([#552](https://github.com/danjdewhurst/story-skills/issues/552))
- `bun run check:package` and `bun run release` now run on Windows. There npm and the installed `story` bin are `.cmd` shims, which Node refuses to start without a shell (`EINVAL`), so the scripts now run them as node and the shim's script. CI runs `check:package` on Windows and macOS too. ([#573](https://github.com/danjdewhurst/story-skills/issues/573))
- `story reindex`, and the commands that run it (`add`, `rename`, `move`, `doctor --fix`), no longer silently drop notes you write in a registry. Text under the `# ` title, before or after a generated table, under the chapter total, and in `### ` subsections now stays where you wrote it; only the registry tables are rebuilt, including one split by a git conflict. A `## ` heading inside an HTML comment no longer splits a section in two. ([#580](https://github.com/danjdewhurst/story-skills/issues/580))
- The eval runner (`evals/run-skill.js`) now gives the model the reference files a skill's `SKILL.md` names, other skills' files included, and asks the eight fixtures whose brief wants a file or frontmatter for exactly that instead of prose. Files that only a reference names load breadth-first up to 48,000 characters. A failed draft or judge call now stays in the summary and its pass count, and a judge reply with two different arrays fails the fixture, while a bracket in its prose such as `[name needed]` no longer does. ([#559](https://github.com/danjdewhurst/story-skills/issues/559))

### Security

- The Publish workflow publishes a tag to npm only if it is on the release commit of its `package.json` version on `main`, and only after that commit's CI run on `main` has passed. npm now goes after the binaries and release assets, from a job in the `npm` environment, and a manual run must be dispatched on `main` or on the tag. A later push to `main` no longer cancels the CI run of the commit before it. ([#544](https://github.com/danjdewhurst/story-skills/issues/544))
- Names and titles can no longer break out of the print and Shunn running heads or `story diagram` labels. A form feed or other control character in the title or author now stays inside the running head's CSS string; before, `author: "Ann\f}} body { display: none } x {"` printed one blank page. `story diagram` writes `#`, `%`, `:`, and backticks in labels, and `#`, `;`, `%`, and `<` in timeline text and dates, as Mermaid entity codes, so `Unit #101; East` no longer renders as `Unit e East`, a `%%{init}%%` in a name no longer changes the diagram's theme, and a colon in a calendar date no longer stops the timeline rendering. ([#590](https://github.com/danjdewhurst/story-skills/issues/590))

## [0.22.1] - 2026-10-06

### Changed

- Skills now ask before they cut, remove, or tag prose. revision-continuity's revision plan names each scene, subplot, or passage it would cut, fold, or move, and the skill waits for the user's approval before editing; the removability audit and length pass propose cuts rather than make them, and the length pass writes chapter `target-words` budgets only once the plan is approved. A single edit the user has already spelled out counts as approved. interactive-fiction fixes `unreachable-chapter` with a choice that leads there, and removes a chapter only as one approved step after a snapshot and a `--dry-run` of each scene and the chapter, listing any `died-in`, `since`, `learned-in`, or progression `from` that would block it; a new Hard Rule repeats this. feedback-triage checks that `.gitignore` lists `dist/`, shows `git status` for the project folder, and, with approval, commits that folder before it tags a feedback round, so the tag holds the text the review copy was built from; a project without git, or a user who declines the commit, takes a `story snapshot` instead and maps old labels with `story compare --snapshot`. ([#543](https://github.com/danjdewhurst/story-skills/issues/543))

### Fixed

- `story import` into a folder that already exists no longer says `--force` never overwrites files: the refusal now says that `--force` deletes every `chapters/chapter-NN.md` and writes the imported chapters in their place, adds missing starter files, keeps `story.md` and the other files, and reindexes. `import --force` into an existing project now holds the project lock from reading the project's language, count unit, and style sheet to the reindex, as the other write commands do, so while another story command is changing the project it refuses with exit code 4 and changes nothing, and the chapters are never built from settings that changed meanwhile. Before, it replaced the chapters and created starter files, then failed at the reindex saying nothing was changed. `story init`'s message is unchanged. ([#541](https://github.com/danjdewhurst/story-skills/issues/541))
- Every file the CLI writes or rewrites goes through a hidden temporary file beside it, which is then renamed over the target. That temporary file now has a fresh random name (`.chapter-01.md.story-<random>.tmp` instead of one ending in the process id) and is created only when nothing is at that name, with its permissions set on the open file rather than by path. A symlink or other file already at that name is never opened or written through, in a real run or a `--dry-run` preview, and a failed write removes only the temporary file it made. The temporary name keeps at most 227 bytes of the target's name, cut at a whole character, so a file name of up to 255 bytes in any script (an `--out` name in accented or non-Latin letters, say) can be written; before, a long name in two-byte characters could fail with `the name is too long`. `story validate` still reports temporary files left by an interrupted write under either name.
- The `draft-next-chapter.yml` template's publish job now refuses a draft branch that contains a merge commit, since a merge can carry changes of its own that a plain `git log` does not list. Its file check and secret check read a merge's own changes too (`git log -m`), and the secret check reads files git would call binary (`--text`), so a NUL byte in a chapter no longer hides the API key from it. In the draft job, the agent's git and the bundle step's git read no global or system git config (`GIT_CONFIG_GLOBAL=/dev/null`, `GIT_CONFIG_NOSYSTEM=1`). Copy the updated template into your story repository to pick this up.
- `--out` refuses a path inside a `.git` folder for `export`, `build` (the codex folder included), `synopsis`, and `diagram`, in any letter case and through a symlinked folder, with exit 4: `Refusing to write generated output to .git/config: it is inside a .git folder. Choose a path outside .git`. On Windows, `.git.`, `.git ` and `GIT~1` count as `.git` too. Only the folders below the project (or, for a path outside it, below the folder the two share) are checked, so a book inside a folder named `.git` still builds to its own `dist/`. `init` and `import` refuse a project folder inside a `.git` folder the same way. Generated output could otherwise replace a repository's own files, such as `.git/config`, which the draft-next-chapter workflow's agent is not meant to touch.
- Builds keep the spaces a writer types as text. The EPUB, DOCX, Shunn (markdown, DOCX, and PDF), HTML review, and print builds collapsed every Unicode space to a plain one, so the no-break space (U+00A0) inside French « » and the narrow no-break space (U+202F) before ? and ! became spaces a line could break at, and the ideographic space (U+3000) that opens each Japanese paragraph was dropped, leaving vertical EPUB paragraphs with no indent. Only spaces, tabs, and line ends in the markdown source now collapse, so typed spaces inside a line reach every build. A typed space that opens a paragraph is that paragraph's indent, the first paragraph's included, in the builds with no first-line indent of their own: the EPUB and the HTML review copy (unless `build-style` sets `paragraphs: indented`), the markdown export, the narration script, and Twee. Print (unless `paragraphs: block`), DOCX, and the Shunn builds indent first lines themselves, so they still drop a typed indent rather than indent twice. A line of nothing but typed spaces at either end of a chapter is still blank, and in the narration script such a line between paragraphs is now blank too, as in the other builds. A scene break spaced with no-break spaces is still a scene break, and is now a `[pause]` in the narration script. Books without typed spaces build byte for byte as before. ([#542](https://github.com/danjdewhurst/story-skills/issues/542))

## [0.22.0] - 2026-10-06

### Added

- Collections and anthologies can credit each story's writer and the book's editor (#473). A chapter's new `author` field (a name, or a list) prints under the story's heading as `by Ines Calder` in the markdown, EPUB, DOCX, HTML review, print, and Shunn builds and the codex, and never counts toward word counts. `story.md`'s new `editor` field credits the editor as `Edited by Miriam Hale` on the HTML, print, codex, and Shunn title pages, heads the print and Shunn running heads when no author is set, and joins the metadata sheet. The EPUB names editors as creators and story authors as contributors, each with its MARC role (`edt`, `aut`); a book by its authors alone keeps its plain `dc:creator` entries. The `byline` and `edited-by` build labels are translated in every language pack that has labels. `story validate`, the schema, and the known frontmatter keys cover both fields. ## [0.21.0] - 2026-10-04

### Added

- `story continuity`, `story knowledge`, and `story context` follow the paths of choices in a branching book. Once any chapter has `choices`, a chapter counts as later than another only when a path of choices leads from one to the other, so a death, revival, fact, or progression on one branch no longer reaches its sibling branches: a character killed on the fight branch may appear on the flight branch without a `posthumous-appearance`, and may learn there without a `posthumous-learning`. A chapter two branches rejoin at is checked against both, so a character who dies on either branch is dead there, and a revival counts only when every path from the death passes through it. Two chapters dated on different days still compare by date. Chapters in one loop, and chapters no path reaches, compare by date and then by number, as in a linear book. `story knowledge` lists only facts learned on a path to `--at`; `story context` leaves out sibling branches' facts, scenes, threads, and deaths. `continuity/state.md` is checked against the paths that lead to `current-chapter`, and the new `state-differs-by-path` warning reports an artifact those paths leave with different owners or locations, in place of a `state-object-drift` that no snapshot could fix; an `object-state` entry with a `since` after every branch's change, such as where they rejoin, settles it. A character may list the same `fact` once per branch when neither `learned-in` chapter leads to the other. A status progression on one branch is a `progression-death-conflict` when the character is dead there, even if another branch revives them. Progressions apply in the order of the paths, even where a path runs against the chapter numbers. Linear books are unchanged, as are promise, question, and clue ledgers, the clock and route checks, and the `story series` and `story diagram` lifelines, which still read chapter numbers. ([#358](https://github.com/danjdewhurst/story-skills/issues/358))

After drafting it runs `story continuity` with the other maintenance commands, in the same place discovery-drafting does, because `story next` can name continuity errors and still exit 0. Registry rows, including `chapters/_index.md`, are left to `story reindex`. ([#342](https://github.com/danjdewhurst/story-skills/issues/342))
- A `.story.lock` written on another machine is taken over once it is older than 10 minutes, so a lock left by a killed container or cloud agent no longer blocks every later write. A newer lock from another machine is left in place, and the command still tells you to delete `.story.lock`. ([#349](https://github.com/danjdewhurst/story-skills/issues/349))
- `story context` estimates tokens in Chinese, Japanese, Thai, Lao, Khmer, and Burmese from the words `story wordcount` splits those scripts into, instead of whitespace-separated runs. Spaced text still costs 4 tokens per 3 words. Han and katakana, including the katakana long-vowel mark, cost 2 tokens per 3 characters; hiragana costs 1 per 2; each Thai, Lao, Khmer, or Burmese word costs 1. The rates are added and rounded up once. The printed estimate line states those rates. A long passage in one of those scripts now fills the budget and is listed under "Left out to fit the budget", where before a whole chapter counted as a couple of tokens. ([#340](https://github.com/danjdewhurst/story-skills/issues/340))
- `story context` includes the book's language contract in story essentials: `language` (`en` when unset), `writing-mode` (`horizontal` when unset), `chapter-numerals` (`western` when unset), and `count-unit` (the unit the book is counted in, including the one its language implies). They are properties of the book, so they are included at every chapter, as their own item ahead of the rest of `story.md`, so a tight budget does not drop them. The `chapter-writing` and `reader-panel` skills say so. ([#343](https://github.com/danjdewhurst/story-skills/issues/343))
- `story context` for a scene no longer includes a fact the POV character learns later in the same chapter. A `knowledge-state` entry whose `learned-in` is the target chapter is included only when an earlier scene's `state-changes` records that fact for the POV character, matched by `fact` id or by the same text aside from case, spacing, and a trailing full stop or exclamation mark, and labelled `reader-knowledge, learned in this chapter, scene N`. Drafting the chapter still lists every fact known by the end of that chapter. ([#344](https://github.com/danjdewhurst/story-skills/issues/344))
- `story continuity` checks location routes within each chapter `strand`, as it already checks the clock. A character at two places on the same date in two strands (the mill in `1990` at 09:00 and the keep in `2020` at 09:20) is no longer `route-too-fast`. Sightings inside one strand are still checked. A journey that really crosses strands is not inferred: scene records have no field for it, so keep those scenes on one strand, or record an intentional finding in `continuity/exemptions.md`. ([#345](https://github.com/danjdewhurst/story-skills/issues/345))
- `story continuity` warns `question-unanswered` when an open question has gone unanswered for twelve or more drafted chapters, counted the same way as the Chekhov gap for promises and clues (chapter files up to the latest drafted chapter, so a skip in the numbering and outline chapters scaffolded ahead do not inflate it); a question introduced in a chapter still in `outline` does not age until that chapter is drafted. The gap is wider than the three-chapter promise and clue gap, and the finding stays a warning, so a mystery's central question does not fail the check. A deliberate hold is recorded in `continuity/exemptions.md` with `code: question-unanswered` and the question's file, the same way an unpaid promise is exempted; `severity` set to `off` for that code silences every one. An unanswered question is still an error only when `story.md` is `status: complete` (`complete-with-open-question`). ([#347](https://github.com/danjdewhurst/story-skills/issues/347))
- `story continuity` treats a `died-in` chapter that is still `status: outline` as a planned death, not one already in force. The character may stay `status: alive`, and a later chapter or scene may still list them. Learning in a later chapter is allowed too. Drafting that chapter opens the dead window: the status must be `deceased`, a later cast is a `posthumous-appearance`, and later learning is `posthumous-learning`. `story knowledge` is unchanged (a `learned-in` on an outline chapter still counts). `story series` and `story diagram` still count the planned death at the end of the book. `story context` shows the character as `alive` in a later chapter until the death chapter is drafted; the death chapter itself still shows `dies in this chapter`. ([#346](https://github.com/danjdewhurst/story-skills/issues/346))
- `story knowledge` and `story context` now use one rule for what a character knows. A fact counts when `learned-in` is not after the chapter in story time (by date when both chapters are dated, otherwise by chapter number), the same clock as deaths. Each listed fact is marked `reader-knowledge` when that chapter has already been read, or the fact is pre-existing, and `character-knowledge` with `do not reveal` when the character learned it in a later-read flashback. Context used to drop that second kind, so a drafter following `story context` wrote the character as not knowing their own past, while `story knowledge` printed the fact with no warning not to reveal it. A fact learned later in story time stays out of both, including one the reader has already read in a flash-forward. In `story context` those facts form their own `What <name> knows that the reader has not seen (do not reveal)` item, packed after the rest, so they never push other knowledge out of the budget and the reader panel can drop them whole. Deaths are unchanged. `story knowledge --json` entries gain `audience` (`reader` or `character`). ([#341](https://github.com/danjdewhurst/story-skills/issues/341))

- `story prose` watch words and `preferred` spellings now match in Chinese, Japanese, Thai, Lao, Khmer, and Burmese text, which puts no spaces between words. Before, they never matched there. - The Shunn DOCX build wrote bold and italic after the font size in each run's properties, against the order the WordprocessingML schema sets, which strict readers can reject. ## [0.18.0] - 2026-09-29

### Added

- `reader-panel` skill: structured simulated reads of a chapter range by five personas (a target-genre reader, a line editor, a sensitivity persona that only flags passages for a human reader, a continuity-minded reader, and a first-page reader), each written to `feedback/round-{N}/{persona}.md` in the feedback-triage file shape with `source: simulated` and `persona`. Personas read only the chapters in range, with `story context` for background. `feedback-triage` labels a simulated round's synthesis, sorts its findings as single-reader, and treats its `ready` verdict as ready for human readers only. ([#293](https://github.com/danjdewhurst/story-skills/issues/293))
- `story prose` compares chapters with the author's own prose. List files or folders of it as `samples` in `style-sheet.md`, such as an earlier book or approved chapters, read as `story similarity --against` reads them. From them `prose` builds a profile: sentence length and spread, paragraph length, dialogue share, filter-word and adverb rates, and 20 signature words. It then warns when a chapter drifts past fixed, documented tolerances in either direction (`prose-baseline-sentences`, `-paragraphs`, `-dialogue`, `-filter-words`, `-adverbs`). The author's own rates replace the fixed `--max-filter-words` and `--max-adverbs` limits. Samples under 2,000 narration words warn `prose-baseline-small` and keep the fixed limits. `--baseline false` turns the comparison off, `--json` adds `data.baseline` and `chapters[].baseline`, and `story validate` checks `samples` (`style-sample-missing`). The `voice-style` and `line-editing` skills set samples and treat a drift as a prompt to reread. ([#292](https://github.com/danjdewhurst/story-skills/issues/292))
- `story similarity [path] --against <file|folder|git-ref>` finds passages of chapter prose that share a run of words with other text: earlier books, a previous draft, or a source. Words are compared lowercased without punctuation, and each run of `--min-words` (default 8, at least 5, settable in `cli-defaults`) or more shared words is a `similarity-shared-passage` warning. The warning gives the chapter's review-copy label, the reference's location, and the shared words, and the report adds per-chapter and total shares. A folder with `story.md` is compared chapter by chapter; any other folder contributes its `.md`, `.markdown`, and `.txt` files; anything else is tried as a git ref, read as `compare --ref` reads one. It supports `--json` and is advisory: it exits 0 unless `severity` promotes the warning. The `editorial-review` skill runs it and says how to report shared text honestly: overlap is not plagiarism, and no match is not proof of originality. ([#291](https://github.com/danjdewhurst/story-skills/issues/291))
- Standalone `story` binaries for writers without Node, built with `bun build --compile` for macOS (arm64 and x64), Linux (x64 and arm64), and Windows (x64). Each release builds every binary on its own OS and smoke-tests it there (`--version` and `validate` on an example), attaches the archives and a `story-skills_<version>_checksums.txt` to the GitHub release, and, with a `HOMEBREW_TAP_DEPLOY_KEY` secret (an SSH deploy key on the tap), updates the formula in `danjdewhurst/homebrew-tap`, so `brew install danjdewhurst/tap/story-skills` installs the CLI. CI builds and runs each binary on its own OS too. The binaries report the same `story --version` as the npm package, which stays the primary channel. ([#296](https://github.com/danjdewhurst/story-skills/issues/296))
- `story series` and `story diagram` read deaths recorded as status progressions, as `story continuity` does. Deaths and revivals are resolved once, in the new `src/deaths.js`, from `died-in`, `revived-in`, `status`, and status progressions in story order. `story series` reads each earlier book's state at its end, in chronological order: a character killed by a progression in book one is reported in book two with the existing `canon-death-status`, `canon-posthumous-appearance`, and `canon-posthumous-learning` codes, a revival in an earlier book clears the death, and a later book that brings a character back with a status progression is not flagged from that chapter on. `story diagram relationships` marks characters dead at the end of the book (by `died-in`, a progression, or `status`) as `deceased`, and adds a `revived` class for those who died and came back. ([#287](https://github.com/danjdewhurst/story-skills/issues/287))

### Changed

- `story validate` and `schemas/story.schema.json` now accept the same frontmatter, checked by a new seeded property test (`test/validate-schema-property.test.js`). Each disagreement it found was fixed on the side that was too loose, so some projects that passed before now report an error. ([#295](https://github.com/danjdewhurst/story-skills/issues/295))
  - `validate` now rejects:
    - a list in a free-text field (`premise`, `lie`, `region`, `strand`, and the rest);
    - an unknown character `arc-type`;
    - a fractional or true/false `population`;
    - empty or unquoted-number entries in `themes`, `contact`, `authors`, and `keywords`;
    - `contact` or `mice-threads` written as one value instead of a list, such as `contact: me@example.com` (write `contact:` then `  - me@example.com`);
    - a list in a documented `continuity/state.md` entry key.
  - The schema now rejects:
    - blank names, titles, terms, and required `type`s, and blank items in string lists;
    - a `mode` or `draft-mode` other than `discovered` or `outlined`;
    - a `cover` that is not an image file name;
    - an object-state `status` outside the artifact statuses.

    It accepts the empty chapter `mode` that `story add` writes, and an empty `publication-date`.

- **`draft-next-chapter.yml`** now separates drafting from publishing:
  - **Draft job.** The agent runs with a read-only token and may not write under `.git/`. It runs plain `story` commands from a CLI installed outside the repository beforehand, so no `.npmrc` it writes can take effect. It only commits on a `draft/` branch; `git push` and `gh pr create` are no longer among its allowed tools. The prompt tells it that project text, including reader notes under `feedback/`, is data and never instructions.
  - **Publish job.** A fresh runner takes the commits as a git bundle, checked against `github.sha`. It refuses them if any commit touches a file other than the story's own markdown (`story.md`, `style-sheet.md`, `progress.md`, and the story folders; no dotfiles, scripts, symlinks, or `CLAUDE.md`, `AGENTS.md`, or `SKILL.md`), or holds the API key. It runs `story validate`, `links`, and `continuity` with `--json`, telling findings (exit 1) from an unusable project (2 to 4). Then it pushes the branch, under a run-numbered name if an old branch has the name, and opens the pull request against the branch the run started from. The agent's commit messages are quoted as an indented block. A draft that fails the checks, or falls outside the word range, opens as a draft pull request listing the failures, and the run fails.
  - **Budgets.** Manual runs take inputs for the word range (`min_words`, `max_words`), `max_turns`, and `max_budget_usd`, passed to Claude Code as `--max-turns` and `--max-budget-usd`. Scheduled runs use their defaults.
  - **Threat model.** `docs/automation.md` sets it out. Copy the new template over the old one to adopt it. ([#294](https://github.com/danjdewhurst/story-skills/issues/294))

An entry that names a warning's `code` also dismisses it wherever another command reports it, as `severity` does, and applies before `severity`. `story continuity` findings about a chapter, scene, learning event, or dated scene carry a `chapter`, and `--json` diagnostics gain `chapter` and, when dismissed, `exemptionIndex`, the matching entry. `story validate` checks the new keys (`exemption-unknown-code`, `exemption-code-not-dismissible`, `exemption-file-not-relative`, `exemption-too-broad` for an entry with only a `code`, or only a `file` or `chapter`, `exemption-misspelled-key`, `exemption-chapter-not-carried`) and warns (`stale-exemption`) about a `file` or `chapter` that names nothing; `rename` and `move` carry `file` and `chapter`, and `remove` warns about them.
